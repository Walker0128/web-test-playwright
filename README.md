# Web Test Playwright- Sauce Demo

## 概要

このリポジトリは、公開されているテスト練習用Webサイト「Sauce Demo」を対象に、手動テストケースとPlaywrightによる自動テストを作成したものです。

- 対象サイト: https://www.saucedemo.com/
- 使用ツール: Playwright / TypeScript
- CI: GitHub Actions

## 対象選定理由

Sauce Demoは、ログイン、商品一覧、カート、チェックアウトなど、ECサイトに近い基本的なユーザーフローを安全に確認できるデモサイトです。

実在するSaaSプロダクトやログイン後の本番画面を対象に自動テストを実行し、そのコードをPublic GitHubリポジトリへ保存すると、アカウント情報、テストデータ、操作影響などのリスクが発生する可能性があります。そのため、本課題では安全で再現性の高いデモサイトを対象にしました。

## テスト観点チェックリスト

以下は、Sauce Demoに対して考えられる主なテスト観点です。
本課題では、この中から代表的な3件を手動テストケース化し、同じ3件をPlaywrightで自動化しています。

### ログイン / 認証

#### 機能

- [ ] 標準ユーザーでログインできること
- [ ] ロックされたユーザーでログインできないこと
- [ ] 存在しないユーザーでログインできないこと
- [X] 誤ったパスワードでログインできないこと
- [ ] Username未入力時にエラーが表示されること
- [ ] Password未入力時にエラーが表示されること
- [ ] ログアウト後、ログイン画面へ戻ること

#### 安全性

- [ ] ユーザー名・パスワードに特殊文字を入力しても、画面がクラッシュしないこと
- [ ] SQLインジェクションを想定した文字列を入力しても、ログインを突破できないこと
- [ ] 不正な入力に対して、システムエラーやスタックトレースが表示されないこと
- [ ] 不正な入力に対して、適切なエラーメッセージが表示されること
- [ ] 空白文字のみ、前後スペース付きの入力でも想定外の挙動にならないこと
- [ ] 長すぎる文字列を入力しても、画面表示や処理が崩れないこと
- [ ] 日本語・絵文字・記号などを入力しても、画面が異常終了しないこと
- [ ] パスワード欄の入力内容が画面上に平文表示されないこと
- [ ] ログイン失敗時に、ユーザー名が存在するかどうかを推測できる詳細なエラーを表示しないこと

### 商品一覧 / 商品表示

#### 商品一覧

- [ ] 商品一覧画面に商品名・価格・画像・Add to cartボタンが正しく表示されること
- [ ] 商品一覧から商品詳細画面へ遷移できること
- [ ] 商品一覧画面でAdd to cartをクリックすると、ボタン表示がRemoveに変わること
- [ ] 商品一覧画面でRemoveをクリックすると、商品がカートから削除され、ボタン表示がAdd to cartに戻ること
- [ ] 複数商品を追加・削除した場合、カート件数が正しく更新されること
- [ ] 商品一覧から商品詳細画面へ遷移できること

#### 商品詳細

- [ ] 商品詳細画面に商品名・説明・価格・画像が正しく表示されること
- [ ] 商品詳細画面でAdd to cartをクリックすると、商品がカートに追加されること
- [ ] 商品詳細画面でRemoveをクリックすると、商品がカートから削除されること
- [ ] 商品詳細画面で追加した商品の状態が、商品一覧画面のボタン表示にも正しく反映されること
- [ ] 商品一覧画面で追加した商品の状態が、商品詳細画面のボタン表示にも正しく反映されること

#### カート

- [ ] カートアイコンをクリックすると、カート画面へ遷移できること
- [ ] 商品をカートに追加できること
- [ ] カートアイコン上の件数が、追加済み商品の数と一致すること
- [ ] 商品を削除した場合、カートアイコン上の件数が正しく更新されること
- [ ] カート画面に追加済みの商品名・価格・数量が正しく表示されること
- [ ] カート画面でRemoveをクリックすると、対象商品がカートから削除されること
- [ ] カートに商品がない状態でCheckoutを実行した場合、チェックアウトへ進めないこと

#### サイドメニュー

- [ ] サイドメニューを開閉できること
- [ ] サイドメニュー内の各リンクが表示されること
- [ ] All Itemsをクリックすると商品一覧画面へ遷移できること
- [ ] Aboutをクリックすると外部ページまたは想定されたページへ遷移できること
- [ ] Logoutをクリックするとログイン画面へ戻ること
- [ ] Reset App Stateをクリックすると、カート状態やボタン状態が初期化されること

#### フィルター・ソート

- [ ] 商品名の昇順で並び替えできること
- [ ] 商品名の降順で並び替えできること
- [ ] 価格の安い順で並び替えできること
- [ ] 価格の高い順で並び替えできること
- [ ] ソート後も商品名・価格・ボタン状態が正しく表示されること
- [ ] カート追加済みの商品がある状態でソートしても、Add to cart / Removeの表示状態が維持されること

### チェックアウト / 注文フロー

- [ ] Checkout画面で購入者情報を入力し、注文確認画面へ進めること
- [ ] 注文確認画面に商品名・価格・数量・合計金額が正しく表示されること
- [ ] Finishをクリックすると、注文完了画面が表示されること
- [ ] Finishボタンを連続で素早くクリックしても、重複注文や二重処理が発生しないこと
- [ ] 注文完了後にBack Homeをクリックすると、商品一覧画面へ戻れること
- [ ] 注文完了後に商品一覧画面へ戻った場合、購入済み商品のAdd to cart / Remove状態が初期化されていること
- [ ] 注文完了後にブラウザバックしても、完了済み注文を再送信できないこと
- [ ] 注文完了後に再度カート画面を開いた場合、購入済み商品が残っていないこと

#### チェックアウト / 注文フロー：郵便番号入力

- [ ] Postal Code が未入力の場合、チェックアウトを継続できないこと
- [ ] Postal Code に半角数字を入力した場合、次の画面へ進めること
- [ ] Postal Code に文字列・記号・スペースのみを入力した場合の挙動が仕様どおりであること
- [ ] Postal Code に長すぎる文字列を入力しても、画面崩れやシステムエラーが発生しないこと
- [ ] Postal Code の前後にスペースがある場合、仕様どおりに処理されること
- [ ] 不正な Postal Code 入力時に、適切なエラーメッセージが表示されること
- [ ] Postal Code 入力エラー後、正しい値に修正すればチェックアウトを継続できること
- [ ] Postal Code 入力値が注文確認画面に不要に表示されないこと

### セッション・画面状態保持

- [ ] ログイン後にページをリフレッシュしても、ログイン状態が維持されること
- [ ] 商品一覧画面でリフレッシュしても、商品一覧が正しく再表示されること
- [ ] 商品をカートに追加した後にリフレッシュしても、カート件数が維持されること
- [ ] 商品をカートに追加した後にリフレッシュしても、Add to cart / Remove のボタン状態が維持されること
- [ ] カート画面でリフレッシュしても、追加済み商品が消えないこと
- [ ] 商品詳細画面でリフレッシュしても、商品詳細情報が正しく再表示されること
- [ ] ログイン後にブラウザバック・リフレッシュを行っても、想定外にログイン画面へ戻らないこと
- [ ] ログアウト後にリフレッシュしても、ログイン済み状態に戻らないこと

### 回帰テストフロー / Regression Flow

- [X] 正常系の購入フローを通して確認すること
  - ログインできること
  - 商品を選択できること
  - カートに商品が追加されること
  - チェックアウト画面へ進めること
  - 購入者情報を入力できること
  - 注文確認画面で商品・価格・合計金額を確認できること
  - 注文を完了できること
  - 注文完了後、Back Homeで商品一覧へ戻れること
  - 注文完了後、カート状態が初期化されていること

### 非機能 / セキュリティ観点

#### パフォーマンス

- [ ] ログイン画面が一定時間内に表示されること
- [ ] ログイン後の商品一覧画面が一定時間内に表示されること
- [ ] 商品詳細画面・カート画面・チェックアウト画面への遷移が極端に遅くならないこと
- [ ] 商品画像や主要UIコンポーネントが正しく読み込まれること
- [ ] ページリフレッシュ後も、表示完了までの時間が許容範囲内であること
- [ ] 操作後の画面反応が遅すぎず、ユーザー体験を損なわないこと
- [ ] 主要操作中に不要なリクエストが大量発生していないこと
- [ ] APIや静的リソースの 4xx / 5xx エラーが発生していないこと

#### ストレステスト / 負荷テスト

- [ ] 複数ユーザーが同時にログイン・商品閲覧・カート操作を行っても、サービスが安定して動作すること
- [ ] 短時間に多数のリクエストが発生した場合でも、システムがクラッシュしないこと
- [ ] 高負荷時にレスポンスが遅くなった場合でも、ユーザーに分かりやすい状態表示またはエラー表示が行われること
- [ ] 高負荷時に注文処理・カート状態・在庫状態などのデータ不整合が発生しないこと
- [ ] 同一操作を連続実行しても、二重注文・二重追加・重複処理が発生しないこと
- [ ] レート制限やアクセス制御がある場合、制限超過時に適切なレスポンスが返されること
- [ ] 高負荷時のログ・メトリクス・エラー内容を確認できること

#### APIリクエスト改ざん・不正利用対策

- [ ] APIリクエストのパラメータを改ざんしても、想定外の商品追加・削除・注文処理が実行されないこと
- [ ] フロントエンド上の操作を経由せずに不正なリクエストを送信しても、権限チェック・入力チェックが正しく行われること
- [ ] 他ユーザーのカート情報・注文情報にアクセスできないこと
- [ ] セッション情報や認証トークンが無効・期限切れの場合、API操作が拒否されること
- [ ] APIエラー発生時に、内部情報・スタックトレース・機密情報がレスポンスに含まれないこと
- [ ] 価格・数量・商品IDなどの重要データを改ざんしても、サーバー側で正しく検証されること
- [ ] 連続したAPI操作や重複リクエストにより、二重注文・二重決済・不整合なカート状態が発生しないこと

#### スクレイピング / Botアクセス対策

- [ ] 短時間に大量アクセスが発生した場合、サービスが不安定にならないこと
- [ ] Pythonなどの自動化ツールによる連続アクセスに対して、必要に応じて制限・検知・ブロックが行われること
- [ ] 商品一覧・商品詳細などの公開情報が、想定外の頻度で大量取得されないこと
- [ ] Botアクセスによって、通常ユーザーの画面表示・操作に影響が出ないこと
- [ ] 不自然なアクセスパターンがログ・監視で検知できること
- [ ] User-Agentやアクセス頻度などに基づき、不正または過剰なアクセスを調査できること
- [ ] レート制限がある場合、制限超過時に適切なエラーレスポンスが返されること

## 手動テストケース

| 項目         | 内容                                                                                                                                                                                                                                                                                                                                                                                         |

| 目的         | ECサイトの主要な回帰テストとして、ログイン、商品選択、カート確認、チェックアウト、注文完了、商品一覧へ戻る流れが成功することを確認する                                                                                                                                                                                                                                                       |
| 前提条件     | Sauce Demoのログインページを開いていること                                                                                                                                                                                                                                                                                                                                                   |

## 自動テスト

上記2件の手動テストケースをPlaywrightで自動化しています。

テストコード:

```text
 tests/saucedemo.spec.ts
```

自動テストは、代表的な異常系ログイン確認と主要ユーザーフローの回帰確認を分けています。

- TC-001: 誤ったパスワードでログインできないこと
- TC-002: ログインから注文完了までのHappy Flow

## ローカル実行方法

### 1. 依存関係をインストール

```bash
npm install
```

### 2. Playwrightブラウザをインストール

```bash
npx playwright install --with-deps chromium
```

### 3. テストを実行

```bash
npm test
```

### 4. HTMLレポートを確認

```bash
npm run report
```

## CI実行

GitHub Actionsで以下のタイミングに自動実行されます。

- `main`ブランチへのpush
- `main`ブランチへのpull request
- 手動実行（`workflow_dispatch`）

CI定義ファイル:

```text
.github/workflows/playwright.yml
```
