# Webテスト課題 - Sauce Demo

## 概要

このリポジトリは、公開デモサイトである Sauce Demo を対象にした手動テストケースおよびUI自動テストをまとめたものです。

- 対象サイト: https://www.saucedemo.com/
- 自動化ツール: Playwright / TypeScript
- CI: GitHub Actions
- 設計方針: Page Object Model

## 対象サイト選定理由

Sauce Demo は、ログイン、商品一覧、商品詳細、カート、チェックアウトなど、ECサイトに近い基本的なユーザーフローを安全に確認できる公開デモサイトです。

当初は実際のSaaSプロダクトを対象にすることも検討しましたが、実アカウントを利用した自動テストをPublicリポジトリやCI上で実行することは、アカウント情報・テストデータ・本番環境操作に関するリスクを伴う可能性があります。

そのため、本課題では安全に再現可能なデモサイトを対象とし、テスト設計、自動化実装、CI実行、保守性を重視した構成にしています。

## テストスコープ

以下のチェックリストは、対象機能に対する主なテスト観点を整理したものです。

### カート

- [ ] 商品をカートに追加できること
- [ ] 商品をカートから削除できること
- [ ] カートアイコンからカート画面へ遷移できること

- [ ] カート画面に選択した商品の商品名、価格、数量が正しく表示されること
- [ ] 空カート状態でCheckoutを実行した場合の挙動が仕様どおりであること

### チェックアウト / 注文フロー

- [x] ログインから注文完了までのHappy Flowが成功すること

- [ ] Back Home で商品一覧画面へ戻れること
- [ ] 注文完了後、カート状態がクリアされること

### セッション / リフレッシュ挙動

- [ ] ログイン後にページをリフレッシュしても、ログイン状態が維持されること
- [ ] 商品一覧画面をリフレッシュしても、商品一覧が正しく再表示されること
- [ ] カート追加後にリフレッシュしても、カート状態が維持されること
- [ ] ログアウト後にリフレッシュしても、ログイン済み状態に戻らないこと

### 非機能 / セキュリティ / CI観点

- [ ] GitHub Actionsでpushおよびpull request時に自動テストが実行されること
- [ ] テストレポートがCI artifactとして保存されること
- [ ] 失敗時にスクリーンショット、動画、traceを確認できること
- [ ] シークレット、認証情報、トークン、個人情報をリポジトリに含めないこと
- [ ] 許可なく公開サードパーティサイトに対して負荷テスト・ストレステストを実行しないこと
- [ ] API改ざん、スクレイピング、Botアクセス確認は、許可された範囲内でのみ実施すること

## 手動テストケース

### TC-001: 無効なパスワードでログインに失敗する

| 項目 | 内容 |
| --- | --- |
| 目的 | 無効なパスワードではログインできず、適切なエラーメッセージが表示されることを確認する。 |
| 前提条件 | Sauce Demo のログイン画面が表示されていること。 |
| テストデータ | Username: `standard_user` / Password: `wrong_password` |
| 手順 | 1. Username に `standard_user` を入力する。<br>2. Password に `wrong_password` を入力する。<br>3. Login ボタンをクリックする。 |
| 期待結果 | ユーザーはログイン画面に留まり、ログイン失敗のエラーメッセージが表示されること。 |

### TC-002: 注文完了までのHappy Flow

| 項目 | 内容 |
| --- | --- |
| 目的 | ログインから商品選択、カート、チェックアウト、注文完了までの主要な回帰フローが正常に動作することを確認する。 |
| 前提条件 | Sauce Demo のログイン画面が表示されていること。 |
| テストデータ | Username: `standard_user` / Password: `secret_sauce`<br>Product: `Sauce Labs Backpack`<br>First Name: `Test` / Last Name: `User` / Postal Code: `100-0001` |
| 手順 | 1. 標準ユーザーでログインする。<br>2. 商品一覧画面が表示されることを確認する。<br>3. `Sauce Labs Backpack` をカートに追加する。<br>4. カート画面を開き、選択した商品が表示されることを確認する。<br>5. Checkoutへ進む。<br>6. 購入者情報を入力する。<br>7. 注文確認画面で商品情報と金額情報を確認する。<br>8. Finishをクリックして注文を完了する。<br>9. 注文完了画面を確認し、Back Homeで商品一覧へ戻る。 |
| 期待結果 | 注文完了メッセージが表示され、商品一覧画面へ戻ることができ、カートバッジがクリアされていること。 |

## プロジェクト構成

```text
.github/
└── workflows/
    └── playwright.yml

 tests/
├── data/
│   └── saucedemo.data.ts
├── pages/
│   ├── base.page.ts
│   ├── cart.page.ts
│   ├── checkout-complete.page.ts
│   ├── checkout-information.page.ts
│   ├── checkout-overview.page.ts
│   ├── inventory.page.ts
│   ├── item-detail.page.ts
│   └── login.page.ts
└── saucedemo.spec.ts
```

自動テストは Page Object Model を採用し、テストシナリオ、画面操作・検証、テストデータを分離しています。

- `tests/saucedemo.spec.ts`: テストシナリオとテストステップ
- `tests/pages/`: 各画面ごとの操作・表示確認・検証処理
- `tests/data/`: ユーザー、商品、チェックアウト情報、メッセージなどのテストデータ

この構成により、現在は2件の代表ケースのみを実装していますが、実務でケース数が増えた場合も、画面単位で保守・拡張しやすくなっています。

## ローカル実行方法

依存関係をインストールします。

```bash
npm install
```

Playwrightのブラウザをインストールします。

```bash
npx playwright install --with-deps chromium
```

テストを実行します。

```bash
npm test
```

HTMLレポートを開きます。

```bash
npm run report
```

## CI Pipeline

GitHub Actions により、以下のタイミングでPlaywrightテストが自動実行されます。

- `main` ブランチへのpush
- `main` ブランチへのpull request
- 手動実行（workflow dispatch）

CIでは以下を実行します。

1. リポジトリをcheckoutする
2. Node.js 24をセットアップする
3. `npm ci` で依存関係をインストールする
4. Playwright Chromiumブラウザをインストールする
5. Playwrightテストを実行する
6. Playwright HTMLレポートをartifactとして保存する

Workflowファイルは以下に配置しています。

```text
.github/workflows/playwright.yml
```

## レポート・デバッグ方針

PlaywrightのHTMLレポートでテスト結果を確認できます。  
また、失敗時の原因調査をしやすくするため、必要に応じて以下のartifactを利用します。

- screenshot
- video
- trace

`test.step()` を利用することで、レポート上でも各テストステップを確認しやすくしています。

## 補足

本リポジトリでは、Publicリポジトリとして公開しても問題がないように、実アカウント、シークレット、個人情報、内部API、実サービスの認証情報は扱っていません。

また、負荷テスト、ストレステスト、API改ざん、スクレイピング、Botアクセス確認などのセキュリティ・非機能テストは重要な観点として整理していますが、明確な許可がない外部公開サイトに対しては実行しない方針です。
